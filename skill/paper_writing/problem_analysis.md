# 问题分析与模型选择

## 目的与高质量共性

问题分析负责把题目语言转换为数学任务，并证明模型选择是由目标、数据和约束推出的。可识别文本中 65/100 篇有明确“问题分析”，其中 62 篇能在该部分附近识别到模型、算法或方法选择；部分论文把这一功能合并到“求解思路”。

## 核心论证链

题目要求 → 数学目标 → 数据特征 → 主要困难 → 模型需求 → 候选方法比较 → 最终选择。

例如，不能直接写“针对问题一，我们采用 XGBoost”。应先说明该问是预测、分类、评价还是优化；样本规模、时间依赖、非线性、缺失或约束有什么特点；模型必须满足可解释性、泛化、实时性或可行性中的哪些要求；再说明所选方法为何匹配，并指出验证方式。

## 实际步骤

1. 为每问写一句可检验的数学目标。
2. 列出影响建模决策的 2–4 个数据/约束事实。
3. 明确难点属于信息不足、非线性、组合爆炸、多目标、时空依赖或不确定性中的哪类。
4. 写出模型所需性质，并比较至少一个合理替代方案；简单方法足够时不强上复杂模型。
5. 说明本问与前问共享哪些输入、参数或中间结果，以及误差如何传递。

## 常见错误

- 模型名堆叠，没有选择理由。
- 把数据预处理步骤当成问题分析。
- 用“效果好、适用广”替代可验证需求。
- 忽略问题间依赖，导致同一变量多套定义。

## 自检清单

- 模型选择能否从前文事实自然推出？
- 是否说明了至少一个主要困难和对应设计？
- 是否区分任务目标、评价指标与求解算法？
- 是否与实际代码和实验完全一致？
