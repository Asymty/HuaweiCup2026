# 阶段手册

时间窗口按比赛进展动态调整，不作为绝对时限。

## Phase 0：选题

A/B/C 分别从问题类型、数据、数学难度、工程量、领域知识、候选模型、风险和完成难度分析全部题目。A 汇总，最终选题必须由人类队长确认。

## Phase 1：形式化

A 定义目标、输入输出、变量、约束、指标和问题依赖；B 完成数据审计与 EDA；C 定义验证方法、风险和泄漏检查。

## Phase 2：最小可行解

顺序为 baseline → 简单模型 → 第一份真实结果。不得在可行链路形成前堆叠复杂方法。

## Phase 3：改进

改进必须基于 B 的真实结果与 C 的验证。A 决定是否采纳，所有路线变化写入 `DECISIONS.md`。

## Phase 4：正式实验

B 运行正式对照、参数实验并保存运行时间与结果；C 完成指标、敏感性、稳健性、泄漏与图表验证。

## Phase 5：MODEL FREEZE

结果稳定且时间压力增大时，A 提出冻结建议，必须由人类队长确认。冻结后仅允许修复 bug、补齐结果和执行必要验证。

## Phase 6：论文

A 负责问题分析、假设、符号和模型；B 提供数据、预处理、实验设置与结果材料；C 负责结果分析、图表、敏感性和评价。所有角色先读 `skill/paper_writing/README.md`。

## Phase 7：整合

A 整合全文；C 做独立事实审计，不进行无边界重写。

## Phase 8：FINAL FREEZE

冻结代码、结果、图、表和论文数值；之后仅允许版式、引用和明显错误修复。最终论文与提交仍须人类确认。
